How · 엔진 공개 API

덱은 네 줄짜리 공개 API로 제어된다

// deck 엔진이 window에 노출하는 공개 API
window.__deckGo(3);          // 4번째 슬라이드로 즉시 이동 (0-base)
window.__deckNext();         // 다음 슬라이드
window.__deckPrev();         // 이전 슬라이드
window.__deckSlides.length;  // 전체 슬라이드 수 — 하드코딩 금지, 런타임 계산

외부 스크립트·리모컨·발표자 창까지 모두 이 4개 함수만으로 내비게이션을 완전히 제어한다.

요지

엔진 제어는 전역 API 4개로 끝난다.

전환

"이제 진짜 CDN 라이브러리들을 하나씩 올려보겠습니다."

핵심

  • __deckGo는 0-base 인덱스
  • 슬라이드 수는 절대 하드코딩하지 않는다 — slides.length가 유일 진실원

Chart.js · CDN 위에서 그린 차트

무거운 라이브러리일수록 지연 로드가 답이다

* 코어 번들 근사치(KB, gzip) — 배포 버전에 따라 오차 있음. animation:false로 deck 전환과 충돌을 막는다.

요지

Mermaid 하나가 나머지 세 라이브러리를 합친 것보다 크다.

핵심

  • 차트가 필요 없는 덱엔 Mermaid를 넣지 않는다 — feature 모듈 원칙과 동일
  • Chart.js는 animation:false 필수 — 아니면 슬라이드 전환 애니메이션과 겹쳐 깨진다

Mermaid · 다이어그램 자동 배치

라이브러리 초기화는 엔진 스크립트 뒤에 둔다

flowchart LR
    A[deck 엔진 로드] --> B[슬라이드 마운트]
    B --> C[CDN 라이브러리 초기화]
    C --> D[Chart.js / Mermaid / KaTeX / Iconify]
    D --> E[렌더 완료]

순서가 바뀌면 deck 엔진의 첫 더블 rAF 타이밍과 경쟁해 레이아웃이 흔들릴 수 있다.

요지

초기화 순서 하나가 레이아웃 안정성을 좌우한다.

핵심

  • core-js가 먼저 슬라이드를 배치하고, 라이브러리는 그 뒤에 얹는다
  • mermaid.initialize는 startOnLoad:true로 DOM의 pre.mermaid를 자동 스캔한다

KaTeX · 수식 렌더링

리빌 지연은 등차 함수 하나로 계산된다

각 리빌 요소의 지연 \( d_i \)는 기준값 \( d_0 \)에 순번만큼 더해진다.

$$ d_i = d_0 + i \cdot \Delta t \qquad (\Delta t \approx 0.06\text{–}0.1\text{s}) $$

\( i \) 는 요소 순번, \( \Delta t \) 는 슬라이드 안에서 쓰는 스태거 간격이다.

요지

스태거 애니메이션은 복잡한 로직이 아니라 등차수열이다.

핵심

  • --d 변수 하나로 모든 리빌 타이밍을 제어한다
  • 간격이 너무 크면 지루하고, 너무 작으면 리빌 효과가 안 보인다 — 0.06~0.1s가 실전 구간

Iconify · 아이콘 셋 통합

아이콘 태그 하나로 여러 세트를 섞어 쓴다

lucide
가볍고 일관된 라인 아이콘 — UI 전반 기본값으로 사용한다.
Material Design Icons
세부 아이콘이 필요할 때 폭넓은 커버리지를 제공한다.
Simple Icons
브랜드·서비스 로고 — 기술 스택 표시에 적합하다.

data-icon="세트:이름" 하나로 수천 개 아이콘 세트를 즉시 불러온다.

요지

Iconify는 세트를 하나로 통일하지 않아도 섞어 쓸 수 있다.

핵심

  • data-icon 속성의 접두사가 세트를 결정한다 — lucide/mdi/simple-icons 등
  • 런타임에 필요한 아이콘만 개별 요청 — 전체 세트를 미리 받지 않는다
