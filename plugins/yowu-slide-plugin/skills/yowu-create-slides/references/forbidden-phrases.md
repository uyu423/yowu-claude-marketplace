# 금지 문구 목록

> 가이드 §2.4 기반. Step 5 Append 전, Step 6.5 자기 검증 시 대조한다.

**적용 범위**: LLM이 **자체 생성한 문장**에만 적용. 사용자가 직접 제공한 아웃라인·본문의 문구는 변경하지 않는다 — 메타 블록에 소프트 경고만 기록한다.

---

## 1. 강제 금지 (HARD — 발견 시 문장 폐기·재작성)

| 금지 문구 | 문제 | 교체 원칙 |
|-----------|------|---------|
| "혁신적인", "차세대", "최첨단", "cutting-edge" | 내용 없음 | 구체 메커니즘 기술 |
| "시너지", "synergy" | 구체성 결여 | 어떤 결합이 어떤 결과를 내는지 |
| "패러다임 전환", "paradigm shift" | 과장 | 무엇이 무엇으로 변하는지 |
| "고객 중심의" | 자기 선언 | 구체 정책·행동 |
| "엔드 투 엔드", "end-to-end" (범위 불명확) | 범위 모호 | 실제 시작과 끝 명시 |
| "원활한", "seamless" | 측정 불가 | 측정 가능한 성능 지표 |
| "In today's fast-paced world…" / "디지털 전환의 시대에…" | 통속 오프닝 | 구체 장면·통계 |
| "솔루션" 단독 사용 (`\b솔루션\b`이 앞뒤 수식어 없이) | 모호 | 무엇을 해결하는지 명시 |

**주의**: 환언(paraphrase)으로 해결하지 않는다. 해당 문장 전체를 폐기하고 재작성.

---

## 2. 경고 수준 (SOFT — 메타 블록에 기록, 재작성 권고)

| 문구 | 권고 |
|------|------|
| "다양한", "여러가지" | 정확한 수 또는 예시로 교체 |
| "최적의" | 최적화 기준 명시 |
| "효율적인" | 측정 기준 명시 |
| "지속적으로", "적극적으로" | 구체 행동·빈도로 교체 |
| "~을/를 통해" 남용 | 인과 관계를 직접 서술 |

---

## 3. 이모지 정책 (§2.3, §9.8)

| 구분 | 허용 여부 |
|------|---------|
| 제목 끝 장식 이모지 (🚀, ✨) | **금지** |
| 불릿 머리 이모지 (✅, 💡) | **금지** |
| card-grid `card-icon` | **허용** — 역할 구분 |
| flow `wf-icon` | **허용** — 단계 구분 |
| 상태 표시 아이콘 (경고, 성공) | **허용** — 접근성 보조 시 |

**원칙**: 기능적 아이콘(역할 구분, 상태 표시)만 허용. Iconify 사용 시 Lucide 계열 선호 (`lucide:check`, `lucide:x-circle` 등).

---

## 4. 자기 검증 프로토콜

1. Step 5 append 완료 후, 생성한 모든 제목·본문을 §1 HARD 금지 목록과 대조
2. 금지 문구 발견 시 해당 슬라이드를 Edit으로 재작성
3. 사용자 직접 입력 텍스트에서 금지 문구 발견 시: 메타 블록에 `[SOFT WARN: 슬라이드 N — '혁신적인' 포함 (사용자 입력 보존)]` 기록
4. §2 SOFT 금지 문구는 재작성 강제 없음. 메타 블록에 목록만 기록
