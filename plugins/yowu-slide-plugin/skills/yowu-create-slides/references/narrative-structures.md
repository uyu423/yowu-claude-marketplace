# 서사 구조 가이드

> 가이드 §4, §11 기반. Step 3 아웃라인 플래닝 전에 구조를 선택하고 이 파일을 참조한다.

---

## 1. 서사 구조 결정 트리 (§4.1)

```
Q1. 청중이 경영진·구매 결정자이며 시간이 짧은가?
  ├─ YES → Pyramid Principle
  └─ NO  → Q2

Q2. 청중이 해결할 문제를 이미 인식하고 있는가?
  ├─ YES (내부 팀·같은 분야 전문가)
  │      → SCQA  (기본값)
  └─ NO  → Q3

Q3. 청중이 고통을 능동적으로 찾고 있는가 (RFP·파일럿 등)?
  ├─ YES       → SCQA 또는 BAB
  ├─ UNCERTAIN → StoryBrand
  └─ NO        → PAS
```

---

## 2. SCQA — 기본값 (권장 20–30분)

| 슬롯 | 슬라이드 수 | 역할 |
|------|------------|------|
| S (Situation) | 2~3장 | 청중이 동의하는 현재 상태 |
| C (Complication) | 3~4장 | 그 현재에서 생긴 새 문제 |
| Q (Question) | 1장 | 질문만 크게 |
| A (Answer) | 전체의 50% 이상 | 해법·증거·데모 |

**SCQA 슬롯 제목 예시**

| 슬롯 | 제목 예시 (결론형) |
|------|-----------------|
| SITUATION | "현재 배포는 수작업 롤백에 의존하고 있다" |
| COMPLICATION | "트래픽이 2배 늘면서 롤백 빈도가 3배 증가했다" |
| QUESTION | "어떻게 하면 자동 복구와 가시성을 동시에 확보할 수 있을까?" |
| ANSWER | "오픈텔레메트리 파이프라인 하나로 두 문제를 동시에 해결한다" |

---

## 3. PAS — 10–20분

| 슬롯 | 슬라이드 수 | 역할 |
|------|------------|------|
| P (Problem) | 2~3장 | 현재 고통 |
| A (Agitate) | 2~3장 | 방치 시 비용 (손실 프레이밍) |
| S (Solve) | 나머지 | 해법 + 증거 |

---

## 4. BAB — 5–15분

| 슬롯 | 슬라이드 수 | 역할 |
|------|------------|------|
| Before | 1~2장 | 현재 고통 상태 |
| After | 1~2장 | 해결된 미래 상태 |
| Bridge | 나머지 | 경로 (= 제품·솔루션) |

---

## 5. Pyramid Principle — 경영진 10–30분

| 슬롯 | 슬라이드 수 | 역할 |
|------|------------|------|
| 결론 선언 | 1장 | 최상단 — 핵심 메시지 선제 공개 |
| 근거 A·B·C (MECE) | 각 3~5장 | 서로 겹치지 않고 빠짐없는 근거 |
| 종합 + 다음 단계 | 1~2장 | 요약 + 구체 행동 요청 |

---

## 6. StoryBrand — 20–40분 (청중이 영웅)

| 슬롯 | 슬라이드 수 | 역할 |
|------|------------|------|
| 주인공 (청중의 문제) | 2장 | 청중 현재 상황 |
| 문제 (외적·내적·철학적) | 3장 | 3층위 고통 |
| 가이드 (발표자) | 1~2장 | 청중이 아닌 조력자로서의 발표자 |
| 계획 (3단계) | 3장 | 구체적 실행 단계 |
| 행동 요청 | 1장 | CTA |
| 실패/성공 시나리오 | 각 1장 | 위험과 보상 대비 |

---

## 7. 시간 분배 공식 (§4.3)

| 섹션 | 비율 | 30분 기준 |
|------|------|----------|
| 훅 | 5~8% | 1.5~2.5분 |
| 문제·맥락 | 15~20% | 4.5~6분 |
| 해법·증거 (본론) | 55~65% | 16.5~19.5분 |
| 클로징·CTA | 8~12% | 2.4~3.6분 |
| Q&A 예열 | 1~2% | 0.3~0.6분 |

## 8. 훅 6패턴 (§11.2)

| 패턴 | 슬롯 |
|------|------|
| 충격 통계 | "이 방의 `[N]%`가 `[기한]` 안에 `[사건]`을 겪는다" + 출처 |
| 구체 장면 | "`[날짜]` `[시간]`, 저는 `[상황]`이었습니다" |
| 역설 선언 | "오늘은 왜 `[업계 상식]`이 여러분에게는 맞지 않는지 말하겠습니다" |
| 공통 고통 | "`[역할]`이라면 `[구체 경험]` 해보신 분?" |
| 예상 뒤집기 | "`[제약]` 없이 `[성과]`가 가능할까요?" |
| 참여 유도 | "여러분 팀의 `[지표]`를 채팅에 적어주세요" |

## 9. CTA 4패턴 (§11.3)

| 패턴 | 슬롯 |
|------|------|
| One takeaway | "오늘 한 가지만 가져가신다면, `[핵심 문장]`입니다" |
| 3단계 행동 | "내일 하실 일: (1) `[행동1]` (2) `[행동2]` (3) `[행동3]`" |
| 확실한 다음 약속 | "`[날짜]` `[시간]`에 `[결과물]`을 공유하겠습니다" |
| 희소성 오퍼 | "`[기한]`까지 `[조건]` 분에게는 `[지원]`을 제공합니다" (사실일 때만) |

---

## 10. 반론 선제 슬라이드 템플릿 (§11.4)

- **제목**: "자주 받는 세 가지 의문"
- **본문**: 3개 의문 요약 (불릿 3)
- **노트**: 각 의문에 대한 1문장 답 + 보강 근거
- **배치**: Answer 섹션 후반부 또는 CTA 직전

## 장과 장 사이 — 브리지 문장

서사 구조는 덱 **전체**의 뼈대를 정한다. 그런데 실제로 흐름이 끊겨 보이는 자리는 **구간과 구간 사이**다. 구간이 바뀌는 슬라이드의 마지막 한 줄(`.bridge`, `content-rules.md`)로 그 틈을 메운다.

| 이 장이 끝난 상태 | 브리지 문형 |
|---|---|
| 무엇을 만들었는지 보여줬다 | "이 화면을 채우는 데이터는 **한 건도 우리 것이 아닙니다.**" |
| 문제를 드러냈다 | "그래서 **무엇을 바꿨는지** 보겠습니다." |
| 방법을 설명했다 | "그럼 실제로 **얼마나 줄었을까요.**" |
| 결과를 냈다 | "숫자는 좋습니다. **그런데 이 숫자를 누가 검증했나요.**" |
| 실패를 인정했다 | "여기서 배운 것을 **다음 장 세 줄로** 정리했습니다." |

원칙:

- **결론을 되풀이하지 않는다.** 방금 말한 것을 요약하는 브리지는 자리만 먹는다. 다음 장이 답할 **질문**을 던진다.
- **한 줄이다.** 두 줄이 되면 그건 슬라이드 본문이지 브리지가 아니다.
- 노트의 `<h4>전환</h4>`과 문장을 공유하지 않는다. 화면에 뜬 문장을 발표자가 그대로 읽으면 청중은 둘 중 하나를 버린다.
